Relationship notes

  • All relationships are 1 : N. One user has many tickets, bookings, notifications and can post many announcements.
  • tickets.user_id and bookings.user_id / item_id use ON DELETE CASCADE.
  • tickets.assigned_to and announcements.posted_by use ON DELETE SET NULL.
  • faqs is a standalone knowledge-base table with no foreign keys.
  • Double-booking is prevented at the database level by an EXCLUDE USING gist constraint on approved bookings for the same item.
  • Ticket status follows the state machine: Pending → Assigned → In Progress → Resolved → Closed.
